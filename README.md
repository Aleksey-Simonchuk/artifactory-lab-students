# Лабораторная работа: развёртывание и использование JFrog Artifactory

**Цель работы:** научиться поднимать стенд JFrog Artifactory OSS в Docker
и работать с ним из командной строки: создавать репозитории, публиковать
и скачивать артефакты, проверять их целостность, автоматизировать публикацию
bash-скриптами.

**Время:** 2 пары. **Что сдать:** см. раздел «Отчёт» в конце.

**Материалы в репозитории:**
- `docker-compose.yml` — готовый стенд (Artifactory + PostgreSQL);
- `slides.html` — презентация с теорией (открыть в браузере);
- этот `README.md` — ход работы.

---

## Краткая теория

**Артефакт** — результат сборки проекта (архив, пакет, docker-образ).
Исходники хранят в git, артефакты — в менеджере артефактов. Каждый артефакт
имеет **версию** (формат SemVer: `MAJOR.MINOR.PATCH`) и **контрольные суммы**,
которые Artifactory считает автоматически.

**Типы репозиториев:** `local` — свои артефакты; `remote` — кэширующий прокси
к внешним хранилищам; `virtual` — объединение нескольких под одним URL.

Artifactory управляется через **REST API**, поэтому всё, что делается
в веб-интерфейсе, можно делать из bash через `curl`.

Подробнее — в `slides.html`.

## Подготовка

0.1. Проверьте, что Docker работает:

```bash
docker version
docker compose version
```

0.2. Поднимите стенд из каталога репозитория:

```bash
docker compose up -d
```

0.3. Дождитесь готовности (первый запуск — 3–7 минут, создаётся схема в БД).
Признак готовности — код 200:

```bash
curl http://localhost:8082/router/api/v1/system/health
```

0.4. Откройте http://localhost:8082, войдите с логином `admin` и паролем
`password`. Мастер предложит сменить пароль — придумайте свой и **запомните**:
он нужен во всех дальнейших командах (ниже обозначен `ВАШ_ПАРОЛЬ`).

> Кстати: в свежих версиях Artifactory убрали встроенную базу Derby, поэтому
> в compose рядом поднимается PostgreSQL — посмотрите в `docker-compose.yml`,
> как приложение узнаёт про базу (переменные `JF_SHARED_DATABASE_*`).

## Ход работы

### Задание 1. Свой репозиторий

Создайте в интерфейсе local-репозиторий типа **Generic** с именем
`myapp-local`: **Administration → Repositories → Add Repositories →
Local Repository → Generic**.

Убедитесь через API, что репозиторий появился:

```bash
curl -u admin:ВАШ_ПАРОЛЬ http://localhost:8081/artifactory/api/repositories
```

**Ожидаемый результат:** в списке есть `myapp-local` с типом `LOCAL`
и packageType `Generic`.

> Попробуйте создать репозиторий через REST API (`PUT /api/repositories/...`).
> Вы получите `This REST API is available only in Artifactory Pro` — в OSS
> управление репозиториями доступно только через UI. Это нормально.

### Задание 2. Первая публикация

Соберите «релиз» — каталог с файлами, упакованный в архив:

```bash
mkdir myapp
echo "print('hello from myapp')" > myapp/main.py
echo "1.0.0" > myapp/VERSION
tar -czf myapp-1.0.0.tar.gz -C myapp .
```

Загрузите в репозиторий (путь внутри репозитория вы задаёте сами):

```bash
curl -u admin:ВАШ_ПАРОЛЬ -T myapp-1.0.0.tar.gz \
  http://localhost:8081/artifactory/myapp-local/myapp/1.0.0/myapp-1.0.0.tar.gz
```

Скачайте обратно и сверьте контрольную сумму с оригиналом:

```bash
curl -u admin:ВАШ_ПАРОЛЬ -O \
  http://localhost:8081/artifactory/myapp-local/myapp/1.0.0/myapp-1.0.0.tar.gz
shasum -a 256 myapp-1.0.0.tar.gz
```

**Ожидаемый результат:** при загрузке — JSON с `sha1`, `sha256`, `md5`;
сумма скачанного файла совпадает с суммой из ответа сервера.
Файл виден в UI: **Application → Artifactory → Artifacts**.

### Задание 3. Новая версия

Измените `myapp/main.py`, выпустите и опубликуйте версию `1.0.1`
(не забудьте обновить `myapp/VERSION`).

**Ожидаемый результат:** в репозитории две версии; их sha256 различаются.

### Задание 4. Паспорт артефакта

Получите через API информацию о файле:

```bash
curl -u admin:ВАШ_ПАРОЛЬ \
  http://localhost:8081/artifactory/api/storage/myapp-local/myapp/1.0.0/myapp-1.0.0.tar.gz
```

Теперь **одной командой с конвейером** вытащите из этого JSON только значение
sha256. Подсказка: `grep` + `cut`, или `jq`, если установлен.

**Сдаётся:** сама команда-конвейер.

### Задание 5. Честная загрузка

Artifactory проверяет целостность на приёме, если передать заголовок
`X-Checksum-Sha256`. Загрузите файл дважды:

1. с корректной суммой (посчитайте `shasum -a 256` и подставьте) — успех;
2. с заведомо неверной суммой — отказ.

```bash
SUM=$(shasum -a 256 myapp-1.0.1.tar.gz | awk '{print $1}')
curl -u admin:ВАШ_ПАРОЛЬ -H "X-Checksum-Sha256:$SUM" -T myapp-1.0.1.tar.gz \
  http://localhost:8081/artifactory/myapp-local/myapp/1.0.1-checked/myapp-1.0.1.tar.gz
```

**Сдаётся:** HTTP-коды обоих случаев и текст ответа во втором.

### Задание 6. Поиск через AQL

AQL — SQL-подобный язык поиска по хранилищу. Найдите все свои артефакты:

```bash
curl -u admin:ВАШ_ПАРОЛЬ -X POST \
  -H "Content-Type: text/plain" \
  -d 'items.find({"repo": "myapp-local", "name": {"$match": "myapp*"}})' \
  http://localhost:8081/artifactory/api/search/aql
```

Измените запрос так, чтобы нашёлся **только файл версии 1.0.1** (поле `path`).

**Сдаётся:** итоговый AQL-запрос.

### Задание 7* (повышенная сложность). cleanup.sh

Напишите скрипт, который оставляет в репозитории только **2 последние версии**
myapp, остальные удаляет через API (`curl -X DELETE`). Для проверки
опубликуйте версии 1.0.0–1.0.4 и запустите скрипт.

Подсказки: список папок — `GET /api/storage/myapp-local/myapp/`, сортировка
версий — `sort -V`.

### Задание 8* (повышенная сложность). publish.sh

Напишите скрипт публикации: принимает версию аргументом (`./publish.sh 1.0.2`),
пакует `myapp/` в архив, загружает в репозиторий, **проверяет HTTP-код
ответа** и сообщает об успехе или ошибке. Бонус: скачивает файл обратно
и сверяет sha256.

### Задание 9* (повышенная сложность). deploy.sh

Напишите скрипт «деплоя»: находит в репозитории **последнюю** версию myapp
(не вбитую в код!), скачивает её, распаковывает в каталог `deploy/` и выводит
содержимое `deploy/VERSION`.

Вместе с заданием 8 это полный круг: сборка публикует — сервер забирает.
Так устроены настоящие CI/CD-пайплайны.

### Задание 10* (повышенная сложность). Права доступа

В UI создайте пользователя `developer` и Permission на ваш репозиторий:
читать и загружать можно, удалять — нельзя. Проверьте curl'ом от его имени:

- загрузка файла — успешно;
- удаление файла — отказ.

**Сдаётся:** HTTP-коды обеих операций. Вопрос на понимание: почему
CI-пользователю в реальной жизни не дают право удалять артефакты?

## Отчёт

Сдаётся в любом удобном виде (файл, сообщение):

1. Скриншот списка репозиториев (задание 1).
2. JSON-ответ сервера на загрузку + совпавшие sha256 (задание 2).
3. Команда-конвейер для sha256 (задание 4).
4. Коды ответов для верной и неверной контрольной суммы (задание 5).
5. AQL-запрос на поиск версии 1.0.1 (задание 6).
6. Скрипты `cleanup.sh`, `publish.sh`, `deploy.sh` и вывод их работы
   (задания 7*–9*).
7. HTTP-коды загрузки и удаления от имени `developer` (задание 10*).

**Критерии:** задания 1–6 — «удовлетворительно»; + любые два со звёздочкой —
«хорошо»; все задания — «отлично».

## Устранение неполадок

- **Долгий запуск / UI не открывается.** Первый старт — 3–7 минут.
  Смотрите `docker compose logs -f`. Docker'у нужно ≥ 4–6 ГБ памяти
  (Docker Desktop: Settings → Resources).
- **Порты 8081/8082 заняты.** Поменяйте левую часть в `ports`
  (например, `"18081:8081"`) и используйте новый порт в командах.
- **401 Unauthorized.** Неверный логин/пароль; используйте пароль,
  заданный при первом входе.
- **400 с текстом про Artifactory Pro.** Эта функция недоступна в OSS —
  так и задумано, делайте через UI.
- **Начать с чистого листа:**
  ```bash
  docker compose down -v && docker compose up -d
  ```
