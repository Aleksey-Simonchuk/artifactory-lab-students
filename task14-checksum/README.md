# Задание 14. Честная загрузка (проверка на приёме)

**Что делаем:** просим Artifactory проверить файл прямо во время загрузки.

**Зачем:** в задании 10 мы проверяли файл *после* скачивания. А можно не
дать битому файлу вообще попасть в хранилище: клиент передаёт сумму
заголовком `X-Checksum-Sha256`, сервер сверяет и при несовпадении
отказывает в приёме.

## Шаг 1. Посчитайте сумму архива

```bash
cd ../task14-checksum
cp ../task06-build-app/myapp-1.0.1.tar.gz .
shasum -a 256 myapp-1.0.1.tar.gz
```

Скопируйте длинную строку из вывода.

## Шаг 2. Впишите пароль и сумму

Откройте `checked-upload.sh`, ВПИШИТЕ:
- `PASSWORD="____"` — пароль;
- `SUM="____"` — сумму из шага 1.

## Шаг 3. Загрузите с верной суммой

```bash
chmod +x checked-upload.sh
./checked-upload.sh
```

В конце вывода — `HTTP-код: 201`. Файл принят.

## Шаг 4. А теперь сломайте сумму

В `checked-upload.sh` замените сумму на `0000` и запустите снова.

В конце вывода — `HTTP-код: 409` и сообщение про несовпадение
контрольной суммы. Файл со сломанной суммой **не принят**: хранящийся
в репозитории файл остался прежним. Проверьте — сумма на сервере
должна быть равна хорошей сумме из шага 1, а не `0000`:

```bash
curl -s -u admin:ВАШ_ПАРОЛЬ \
  http://localhost:8081/artifactory/api/storage/myapp-local/myapp/1.0.1-checked/myapp-1.0.1.tar.gz \
  | grep sha256 | sort -u
```

## Результат

Верная сумма → 201, неверная → 409 и файл отклонён.

**В отчёт:** оба кода ответа.

> Именно так CI-системы ловят файлы, побившиеся при передаче по сети.
