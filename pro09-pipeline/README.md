# Pro 9. pipeline.sh — собираем мини-CI/CD

**Что делаем:** склеиваем свои скрипты из pro02 и pro03 в один пайплайн:
публикация → деплой → проверка, что развернулась именно нужная версия.

**Зачем:** пайплайн в CI — это та же цепочка скриптов, где каждый этап
либо успешен, либо весь прогон падает. Сегодня вы его напишете сами.

## Задание

Подготовка: скопируйте каталог `myapp` из задания 6 в папку
`pro02-publish` — скрипт публикации пакует именно его.

Откройте `pipeline.sh`. ВПИШИТЕ три пропуска:

1. команду запуска вашего скрипта публикации из pro02
   (версия передаётся аргументом);
2. команду запуска скрипта деплоя из pro03;
3. условие сравнения: что должно совпасть с чем
   (запрошенная версия и содержимое файла deploy/VERSION).

## Проверка

```bash
chmod +x pipeline.sh
./pipeline.sh 1.3.0
```

Пайплайн должен напечатать «В продуктиве версия 1.3.0».

Проверка на честность: запустите `./pipeline.sh 9.9.9`, не создавая
архива этой версии заранее, — пайплайн должен упасть на этапе публикации
с понятной ошибкой (файла myapp нет / версии нет).

## Результат

**В отчёт:** готовый скрипт и вывод успешного прогона.

> `set -euo pipefail` в начале — это и есть «упасть при первой ошибке».
> Без него пайплайн продолжил бы работу после провального этапа.
