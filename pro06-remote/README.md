# Pro 6. Remote-репозиторий: кэш для внешнего мира

**Что делаем:** подключаем Maven Central через Artifactory и смотрим,
как работает кэширование.

**Зачем:** разработчики не ходят в интернет напрямую — все зависимости
тянутся через Artifactory. Первый запрос идёт наружу, следующие отдаются
из локального кэша мгновенно. Это и скорость, и контроль («что вообще
скачивают наши сборки»), и работа в закрытом контуре.

## Шаг 1. Создайте remote-репозиторий

**Administration → Repositories → Add Repositories → Remote Repository**:
- тип пакетов: **Maven**
- Repository Key: `maven-central`
- URL: `https://repo1.maven.org/maven2`

Сохраните.

## Шаг 2. Скачайте пакет через Artifactory — первый раз

Засеките время (ВПИШИТЕ пароль):

```bash
time curl -s -u admin:____ -o /dev/null \
  http://localhost:8081/artifactory/maven-central/junit/junit/4.13.2/junit-4.13.2.jar
```

## Шаг 3. Скачайте тот же файл второй раз

Та же команда ещё раз. Сравните время — файл уже лежит в кэше
Artifactory, в интернет запрос не ушёл.

## Шаг 4. Найдите файл в дереве

**Artifacts → maven-central** — там появился кэшированный jar.
Это и есть кэш: файлы появляются в нём по мере запросов.

## Результат

**В отчёт:** время первой и второй загрузки, скриншот кэша в дереве.
Ответ на вопрос: чем remote-репозиторий отличается от local?

## Если не получилось

Нужен доступ в интернет с машины. Если тип Maven недоступен в вашей
сборке OSS — сообщите преподавателю, задание выполняется на его стенде.
