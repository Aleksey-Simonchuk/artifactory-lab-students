# Pro 10. Настоящий CI: GitHub Actions

**Что делаем:** переносим наш пайплайн из bash в GitHub Actions — сервис,
который сам запускает сборку при каждом push.

**Зачем:** пока вы запускали `publish.sh` руками. В жизни это делает
CI-сервер на каждый коммит. Файл-пайплайн лежит в репозитории
в `.github/workflows/`.

## Задание

Откройте `publish.yml`. Это workflow: при push в ветку main он собирает
архив и публикует его в Artifactory. ВПИШИТЕ три пропуска
(вы всё это уже делали руками):

1. команду упаковки каталога в архив;
2. флаг curl для загрузки файла;
3. код успешной загрузки.

Обратите внимание, откуда берутся адрес сервера и пароль: их кладут
в **Settings → Secrets** репозитория, а в workflow они подставляются
как `${{ secrets.ART_PASSWORD }}` — пароль никогда не хранят в коде
(вспомните pro05).

## Как это работает

- `on: push` — триггер: запуск при каждом пуше;
- `runs-on` — на какой машине выполняется;
- `steps` — те же шаги, что вы делали в терминале.

Проверить по-настоящему можно, если преподаватель выдал адрес
общего стенда: заполните Secrets и запушьте. Без сервера —
достаточно корректно заполненного файла.
